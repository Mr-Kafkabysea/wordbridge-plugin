## WB-FB-001：增加无需预览的快速模式

- 记录日期：2026-09-11
- 来源：用户日常使用反馈
- 状态：待验证
- 优先级：高频体验问题，优先评估
- 用户原话：
  - “我觉得每天写入前还要预览一下，非常的浪费时间。”
  - “可以添加一个快速模式，不需要预览，直接操作。”
- 使用场景：用户频繁通过 WordBridge 向已打开的 Word 文档执行熟悉、重复的写入操作。
- 当前体验：一次写入需要先调用追加预览，再发起确认写入；独立预览增加了一轮交互，打断连续操作。
- 期望效果：提供可主动开启的“快速模式”。启用后不再执行或展示独立预览步骤，直接进入实际操作流程，减少日常写入的等待和重复交互。
- 初步方向：
  - 保留现有标准模式，供需要先核对内容的场景使用。
  - 增加快速模式，并提供清楚的开启、关闭和当前状态提示。
  - 明确快速模式是单次操作、当前会话还是持久设置，避免用户误判当前模式。
  - 评估快速模式下是否仍保留一次简化确认，以及目标文档变化、连接中断和结果不确定时的处理方式。
- 设计时需验证：
  - 快速模式确实跳过独立预览，不产生等价的重复交互。
  - 操作前仍能定位正确的活动文档，并拒绝目标不明确的请求。
  - 取消、拒绝、连接中断或结果不确定时不会自动重试。
  - 不改变“不自动保存、关闭或切换文档”的现有行为。
  - 写入仍形成一个可识别的 Word 原生撤销步骤。
- 验收候选：用户开启快速模式后，常规追加操作可以从请求直接进入操作流程；关闭快速模式后恢复现有预览流程。


## WB-FB-001 实施进展（2026-09-14）

- 用户确认采用持续快速模式：显式开启后持续到切回普通模式；作用域为当前 MCP 服务进程，重启恢复普通。
- 开发实现为 set_mode/get_mode 与统一 append_text 入口；快速模式跳过独立预览及逐次确认，保留同次后台检查和单步撤销。
- 配套 Skill 与项目规则已更新，开发版本 0.4.0-dev；全局安装版未更新。
