# WordBridge Plugin 安装与更新（试验）

## 用户操作

要求 Windows、64 位 Python 3.14（`py -3.14` 可用）、Codex CLI（`codex` 可用），以及下载 Python 依赖所需的网络。使用工具另需桌面 Word。不要求管理员权限。

取得并检查新版源码或发布 ZIP，解压后在包含 `install.ps1` 的目录打开 PowerShell：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -CheckOnly
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

第一行是可选的只读预检，第二行执行安装或更新。Bypass 仅作用于本次 PowerShell 进程。

| 检测结果 | 入口行为 |
| --- | --- |
| 没有安装 | 准备运行环境，安装 MCP 与 Skill |
| 包版本高于已安装版本 | 显示旧版 → 新版，检查新版后升级 |
| 包版本等于已安装版本 | 显示无需更新；不改文件、依赖和客户端设置 |
| 包版本低于已安装版本 | 拒绝降级 |
| 安装记录、缓存或注册不一致 | 停止并提示问题，不把损坏安装当成正常同版本 |
| 存在中断记录或安装锁 | 停止，先检查此前操作 |

运行命令即请求安装或升级，不另加一次终端确认。版本比较使用数字与预发布标识的语义顺序，例如 `0.3.0-dev.10` 高于 `0.3.0-dev.2`，正式版 `0.3.0` 高于两者。

**更新完成后新建 Codex 任务**，确认配套 Skill 与工具出现，再请求“用 WordBridge Plugin 检查连接，只调用 word_status”。若未加载，重新加载插件或重启客户端。旧任务可能仍使用旧服务。

此入口使用所在目录中的版本，不联网搜索、下载或追踪 GitHub 最新版。你需要先取得新版包；再次运行旧目录的脚本不会获得新代码。私有仓库仍要求访问权限。

## 开发者发布步骤

1. 修改功能后，统一更新 `.codex-plugin/plugin.json` 和 `scripts/mcp_server.py` 中的版本，更新测试期望值与 CHANGELOG。
2. 运行自动化测试、依赖检查和不访问 Word 的 MCP 握手检查。
3. 构建完整源码包，将经过测试的确定版本交付给用户。
4. 用户运行包内同一个安装入口。

同版本按用户约定跳过，不用于修复或强制覆盖。即使改了代码，也必须为待交付的新版本修改版本号。当前升级功能版本为 `0.3.0-dev`，作为预发布测试包交付，不代表稳定版。

在项目根目录构建：

```powershell
.\.venv\Scripts\python.exe scripts/build_plugin.py
```

产物为 `dist/wordbridge-plugin-0.3.0-dev-plugin.zip`。按白名单收集 MCP、Skill、安装脚本、依赖清单和文档，检查插件与 MCP 版本一致；拒绝覆盖已有包。包不含 Python、Word、开发虚拟环境、Git、个人配置、运行日志或真实文档。

## 更新过程与文件位置

- `%USERPROFILE%/.wordbridge/runtime/wordbridge-plugin-<版本>-<唯一编号>/`：每次准备独立运行快照和虚拟环境；虚拟环境建成后不移动。
- 旧安装器的 `%USERPROFILE%/.wordbridge/runtime/wordbridge-plugin/` 可被识别并升级；保留原目录。
- `%USERPROFILE%/plugins/wordbridge-plugin/`：当前轻量插件包，包含同一快照的 Skill 与指向运行环境的 MCP 配置，不含虚拟环境。
- `%USERPROFILE%/plugins/.wordbridge-backup-<编号>/`：升级前的轻量插件备份。
- `%USERPROFILE%/.agents/plugins/marketplace.json`：首次安装添加本插件条目，保留已有名称、显示信息和其他插件；升级时不改市场条目。
- Codex CLI 管理缓存和插件设置；安装器检查注册版本、来源、启用状态以及缓存中的清单、MCP 配置和 Skill 是否与安装包相同。

升级依次执行：识别旧安装 → 显示版本 → 创建新版环境 → 安装并检查依赖 → 检查实际 MCP 握手版本及工具列表 → 备份和切换轻量包 → 调用 `codex plugin add` → 核对注册和缓存 → 写入安装回执。

完成回执位于每个运行目录的 `install-receipt.json`，记录版本、运行路径和上一版位置。CLI 与缓存检查通过不等于新任务已实际调用工具。

安装不调用 Word 工具，不关闭 Word 或保存文档，不主动终止已有 MCP 进程。运行记录位于各运行副本的 `local/runtime/connections/`。运行环境按版本隔离，不自动迁移旧日志；以后若新增用户配置，需另行设计配置迁移。

## 失败恢复

- 新环境、依赖或握手检查失败：旧包和旧运行环境不变；新文件保留，重试使用新的独立目录。
- 升级切换或 CLI 校验失败：恢复旧轻量包；若已尝试 CLI 安装，则通过 CLI 重装旧版并检查注册与缓存。只有检查通过才报告恢复成功。
- 恢复失败、进程被强制结束或首次 CLI 安装结果不明：保留事务记录并阻止继续更新，不宣称已自动恢复。
- 同时只允许一个安装操作。锁文件为 `%USERPROFILE%/.wordbridge/runtime/.wordbridge-install.lock`。
- 事务记录为同目录下的 `.wordbridge-transaction.json`，包含新版位置、旧版备份和恢复命令。发现记录时，先确认安装进程已结束，核对轻量包、CLI 注册和缓存，再由人工恢复。不要直接删除记录后盲目重试。

旧运行环境、备份及失败文件均不自动清理。强制中断和跨进程文件操作不是完整原子事务。自动恢复只处理安装过程内可捕获的失败，不提供任意版本降级命令，也不能回收其他任务已启动的旧进程。

如果安装后的真实工具使用出现问题，保留回执和上一版备份供检查；不把 CLI 成功当成真实 Word 使用已验收。

## 兼容与验收边界

- 用户已确认本机 `0.2.2-dev` 首次安装、连接和追加使用跑通。
- `0.3.0-dev` 的安装/升级/同版跳过与恢复流程通过临时目录测试；pip 和 Codex 写操作在这些测试中模拟。另执行真实已安装版本的只读升级预检和实际 MCP 握手检查。
- 新版本真实客户端升级、另一台电脑及复杂 Word 场景仍需验收。
- 已有独立 WordBridge MCP 配置或全局 Skill 会阻止安装；只检查用户与当前工作目录及祖先目录的相关配置，不扫描所有项目。
- 不自动启用被禁用的安装，不迁移其他市场的同名插件；自定义 CODEX_HOME 暂不支持。
- 不支持以本地插件形式直接在云端 ChatGPT、macOS 或 Linux 运行。
- 沿用现有 pip 源和证书校验；不自动安装 Python、Codex、Word，不自动申请仓库权限。
- 项目许可证尚未选定，不新增授权声明。
