# WordBridge Plugin 最小插件包（尚未完成安装验收）

## 本阶段设计

采用 Plugin Creator 支持的 Codex 兼容格式：仓库根目录就是插件根目录，技术标识为 `wordbridge-plugin`，产品显示名称为 WordBridge Plugin。仓库与本地目录已从 `wordbridge-mcp` 迁移，已有用户需相应更新启动路径；MCP 连接及 Skill 标识 `wordbridge` 和工具名不变。
不复制维护第二份 Skill 或 MCP 源码，不注册市场，不改变用户现有安装。

```text
wordbridge-plugin/
├── .codex-plugin/plugin.json  插件身份、版本及组件入口
├── .mcp.json                  随包 MCP 启动配置
├── skills/wordbridge/SKILL.md  唯一维护的 Skill 源码
├── scripts/                   MCP 与状态窗口
├── requirements.txt           Python 依赖
└── docs/                      公共说明
```

插件清单与 MCP 当前版本均为 `0.2.2-dev`，表示以该开发版为基础的未发布打包实验，不代表已有同版本正式插件发行。
下一次发布前应共同升级版本并更新 CHANGELOG；本步骤不创建 Git 标签或发布。

## 构建

在源码仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe scripts/build_plugin.py
```

输出到 Git 忽略的 `dist/wordbridge-plugin-0.2.2-dev-plugin.zip`。
脚本检查 MCP 与插件版本一致，按明确白名单收集文件，拒绝覆盖已有包。
不包含 `.git`、开发 `.venv`、`local`、日志、真实 Word 文件或个人 Codex 配置。
ZIP 是源码分发产物，不是已经验证可直接导入的安装器；不包含 Python 和 Word。

## 安装前提与待验证项

当前 `.mcp.json` 使用兼容变量 `${CLAUDE_PLUGIN_ROOT}` 指向安装副本内的 `.venv` 与 MCP 脚本，不硬编码开发机路径。
Windows Codex 对该变量在 command/args 中的展开、系统环境（特别是 WINDIR）传递及缓存目录权限，须在独立项目进行真实安装验收。
仅配置文件与打包测试通过，不代表这些运行条件已验证。

首次安装或更新后，最终安装副本必须有自己的 Python 3.14 环境及 requirements.txt 中的依赖，不能复制开发 `.venv`。
README 的环境准备命令应在最终运行副本执行；本步骤没有自动依赖安装器，也未创建市场入口。
Codex 安装可能复制到缓存，因此不能假定在下载目录创建环境后，缓存中的环境也可用。
现有状态窗口在副本的 `local/runtime/connections/` 写快照，缓存可写性与后续数据持久化方案也需要验收。

## 后续安装与更新流程（设计，尚未实现）

1. 从一个确定的 Git 标签或提交取得 MCP、Skill、依赖和清单的同一快照。
2. 准备新版本的独立环境，完成无 Word 的导入、依赖和 MCP 握手检查。
3. 通过客户端安装/更新整个插件，确保实际启动的是新安装副本。
4. 用户同意后停用旧的独立 MCP 配置与全局 WordBridge Skill，避免重复加载；不直接删除。
5. 新任务加载 Skill 和工具，并进行只读 word_status 验收；失败保留旧版本供恢复。

下载、依赖准备、客户端安装、服务重载不是一个天然原子操作。本项目尚未实现自动回滚或后台更新。
GitHub 推送不会自动更新用户安装；旧进程也不会因文件变化自动切换版本。
MCP 保持通用协议能力，此插件包目前仅面向 Windows 本地 Codex，不能据此宣称云端 ChatGPT 或其他客户端可运行。
项目许可证尚未选择，不新增授权声明。
